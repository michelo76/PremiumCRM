# Now Playing Info — Control4 driver

A Control4 DriverWorks driver that works out **what is playing in a room** and shows it as a
rich "about what's playing" page (poster, title, episode, synopsis, cast, ratings, progress)
behind a **Navigator button** (UI Button proxy web view). It also publishes **variables** and
**events** for Composer programming. It is informational only and never controls playback.

Sources: Roku (ECP), Apple TV (through the companion pyatv bridge in `bridge/`), Home Assistant
media players, and Control4 room media. Metadata: TMDB, OMDb (IMDb / Rotten Tomatoes /
Metacritic), Gracenote (optional), iTunes + MusicBrainz (keyless).

The dealer documentation shown in Composer is [`driver/www/documentation.html`](driver/www/documentation.html).

## Architecture

```
                 ┌───────────────────────── Control4 controller ─────────────────────────┐
 Roku :8060 ◄────┤ np.providers.roku ─┐                                                   │
 ATV bridge ◄────┤ np.providers.bridge├─► np.providers.multi ─► np.engine ──► on_change ──┤
 Home Asst. ◄────┤ np.providers.ha  ──┤    (pick/merge/stale)     │   ▲  state doc (JSON) │
 C4 room vars ──►┤ c4.room → static ──┘                           │   │                   │
                 │                                np.enrich.pipeline (TMDB/OMDb/GN/music) │
                 │                                                    ▲ deps (c4.deps:     │
                 │  c4.app (wiring) ◄──────────── engine events ──────┘  C4:url, timers,   │
                 │   ├─ c4.variables → C4:SetVariable (47 vars, STATE_JSON last)  Persist) │
                 │   ├─ c4.events    → C4:FireEvent (12 events)                            │
                 │   ├─ proxy 5001   → URL_CHANGED / ICON_CHANGED                          │
                 │   ├─ SendDataToUI("NOW_PLAYING", {state=json+sent_at})                  │
                 │   ├─ c4.artwork   → LAN images → data: URIs (remote apps)               │
                 │   └─ c4.httpserver→ optional LAN  GET / , /api/state                    │
                 └───────────────┬───────────────────────────────────────────────────────┘
                                 │ Navigator JS API (works remotely)
                    www/index.html (web view): subscribeToVariable("STATE_JSON"),
                    subscribeToDataToUi, sendCommand("GET_STATE") → ExecuteCommand/UIRequest
```

* `driver/np/` — platform-agnostic core (no `C4` reference). The `deps` contract and config
  schema are documented in the header of `driver/np/engine.lua`; the published state document
  (schema 1) is defined in `driver/np/schema.lua`.
* `driver/c4/` — Control4 glue. `driver/driver.lua` only forwards entry points to `c4.app`
  under `xpcall`, so a Lua error never kills the driver.

## Build and test

```bash
cd control4-now-playing
lua5.1 tests/run.lua              # all specs (core + glue); also: luajit tests/run.lua
lua5.1 tests/run.lua c4/          # glue specs only;  -v for verbose
python3 tools/build.py            # validate + build/now_playing_info.c4z (+ manifest)
python3 tools/build.py --check    # validate only
python3 tools/build.py --smoke /tmp/c4z-check   # build, unzip, load driver.lua FROM the unzipped
                                                # tree with the C4 mock (proves dotted requires
                                                # and www/ resolve from the package layout)
SOURCE_DATE_EPOCH=1794398400 python3 tools/build.py   # reproducible zip
node tools/icons/render.js        # re-render icons from tools/icons/*.svg (Playwright)
```

The c4z **must** be named `now_playing_info.c4z`: `controller://driver/now_playing_info/` maps
to its `www/` folder (web view URL and Navigator icons).

`build.py` checks that `driver.xml` is well-formed, that every referenced file exists (script,
documentation, icons, `www/index.html`), that every `require("a.b")` resolves inside the
package, stamps `<version>` (from `c4/version.lua`, `major*10000+minor*100+patch`),
`<modified>` and `BUILD_DATE` in the packaged copy only, and zips `driver/` in a deterministic
order (driver.xml, driver.lua, then sorted; junk excluded; fixed timestamps).

## Installing

1. `python3 tools/build.py` → `build/now_playing_info.c4z`.
2. Composer Pro: Driver › Add or Update Driver or Agent › select the c4z. Add **Now Playing
   Info** to a room.
3. Configure properties (see the Documentation tab), run **Test Metadata Sources**.
4. Room › Navigators › Watch/Listen: make **Now Playing** visible; refresh Navigators.
5. Apple TV only: run the bridge (`bridge/README.md`).

## Data sources and what they can tell you

| Source | App | Title | Episode / S·E | Artist/album | Play/pause | Position/duration | Artwork | Notes |
|---|---|---|---|---|---|---|---|---|
| Roku ECP | yes | **no** | no | no | yes | yes | app icon | Roku TV tuner: channel + program (guide data). Needs "Control by mobile apps" = Default/Permissive |
| Apple TV bridge (pyatv) | yes | if the app publishes it | often | yes (Music) | yes | yes | yes (LAN URL, embedded) | some DRM/live apps publish nothing; `movie`/`live_tv` are heuristics |
| Home Assistant | often | yes | yes | yes | yes | yes | yes (LAN proxy, embedded) | the catch-all (Sonos, Plex, Kodi, Chromecast, Android TV, Roku titles…) |
| Control4 room media | no | yes | no | yes | **no** (shown as playing while room on) | no | sometimes (IMAGEURL) | 1031 XML is undocumented; tolerant parser |
| TMDB | – | match | episode details | – | – | runtime | posters, backdrops, logos | free key; v3 key or v4 token |
| OMDb | – | – | – | – | – | – | – | IMDb/RT/Metacritic ratings (IMDb has no public API) |
| Gracenote | – | live program | – | – | – | – | yes | licence-gated, optional, **untested against the live API** |
| iTunes + MusicBrainz | – | – | – | album, year, tracks | – | – | album art | keyless |

Several sources can be active; the engine picks the most "active" (playing > buffering > paused
> stopped/idle > off, ties by order Roku, Apple TV, HA, room) and merges titles from a source in
the same physical-device group ("Home Assistant Entity Is = Same Device As Roku/Apple TV").

## Page ↔ driver protocol

* Variable `STATE_JSON` (STRING) holds the full state document (schema 1, `np/schema.lua`)
  plus a leading `"sent_at": <controller epoch s>` — rewritten only when the state version changes.
* Every state change also goes out as `C4:SendDataToUI("NOW_PLAYING", { state = json })`.
* `C4.sendCommand("GET_STATE", "{}", true, false)` → `ExecuteCommand("GET_STATE")` → an immediate
  push (always, even if nothing changed; cheap: memoized JSON + `sent_at` splice).
  The synchronous form arrives in `UIRequest("GET_STATE")`, which returns the XML-escaped JSON.
* `sent_at` is spliced into the engine's memoized JSON in the glue (`{"sent_at":N,...`); the page
  uses it to correct controller/device clock skew. LAN `/api/state` uses the engine ETag (not
  `sent_at`) so `If-None-Match` → 304 keeps working, and sends a `Date` header.
* LAN-only artwork (`10/8`, `172.16/12`, `192.168/16`, `*.local`, single-label hosts…) is
  downloaded on the controller (≤ 256 KB, 12 cached) and replaced by a `data:` URI in the state
  document only; the Control4 variables always keep the original http URL.

## Verification status

**No real Control4 controller was available.** Everything listed as tested ran in
simulation only: `tests/c4/c4_mock.lua` mimics the DriverWorks API with the verified signatures
(it records variable order, enforces the OnDriverInit restrictions, drives timers with a fake
clock, scripts `C4:url` replies, variable listeners, server sockets and c4z file access).

Tested (simulation, lua5.1 + LuaJIT): init order / variable IDs, LateInit start and
`URL_CHANGED` after 3 s, Roku + HA → variables / `STATE_JSON` / DataToUI / events / icon, enrichment
→ Details Available, pause/resume/stop, property change reconfiguration without timer leaks,
GET_STATE via ExecuteCommand and UIRequest, room media XML variants (TITLE/ARTIST/ALBUM/IMAGEURL
plain + base64, LINE1-3, CDATA, attributes, JSON, empty, garbage), room power gating, LAN artwork
embedding (incl. oversize and failure), LAN HTTP server (GET /, /api/state 200 → 304, 404, 405,
HEAD, split chunks, 413), destroy cleanup, actions, redaction of keys in logs/prints,
driver.xml ↔ Lua consistency, and a smoke test that loads driver.lua from the unzipped c4z.
The web UI was tested in Chromium only, not in the real Navigator web view (Gecko 96 based).

**Check these first on real hardware** (assumptions, in order of risk):

1. **Room "CURRENT MEDIA INFO" (1031) XML shape** — undocumented. Run *Print Room Media Info*
   with a few sources and compare with `c4/room.lua`. Also check `POWER_STATE` (1010) values
   (assumed `1/0` or `ON/OFF`; fallback: CURRENT_SELECTED_DEVICE ≠ 0).
2. **Navigator JS API payload wrappers** — what `onDataToUi` / `onVariable` actually receive
   (the page accepts `{"NOW_PLAYING":{"state":…}}`, `{"state":…}`, `{"STATE_JSON":…}`,
   `{"name":"STATE_JSON","value":…}`, raw string) and whether `UIRequest`'s return is unescaped.
3. **`C4:SendDataToUI` 2-argument form** (`"NOW_PLAYING", {state=…}`) and its size limit with
   embedded artwork (state can reach ~350 KB with a 256 KB image); same for the size limit of
   a STRING variable (`STATE_JSON`). If either is limited, lower the artwork cap.
4. **Dotted `require("np.engine")`** resolving inside the c4z (proved only against the unzipped
   tree with plain Lua `package.path`).
5. `C4:url` delivering **binary bodies** intact (artwork embedding) and `C4:Base64Encode` on them.
6. `C4:ServerSend` followed immediately by `C4:ServerCloseClient` flushing the response; whether
   `OnServerDataIn` chunks need `C4:CreateServer(port, delimiter)` instead of the 1-arg form.
7. `ICON_CHANGED` state ids / `navigator_display_option` rendering, `URL_CHANGED` timing.
8. `C4:DebugLog` existing on the target OS (falls back to `C4:ErrorLog`).
9. The UI Button web view on the on-screen (TV) Navigator — undocumented, assumed unsupported.
